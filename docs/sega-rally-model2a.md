# Sega Rally Championship (Model 2A) port

This project (a fork of the Daytona USA recompilation, now covering Sega
Model 2 games generally) supports Daytona USA (`daytona93`, `daytona`; Model 2)
and Sega Rally Championship (`srallyc`; Model 2A). This document covers what
was added for Sega Rally. It uses the same approach as upstream: the i960
main CPU, the TGP (MB86233) and the sound 68000 are recompiled ahead of time
from the user's own ROM set into native C++. No ROM bytes or generated code
are committed; only seed lists (address lists we derived) are.

Build and run:

    python3 scripts/setup.py                      # as upstream
    python3 scripts/recompile.py --set srallyc --build-dir build-srallyc
    build-srallyc/daytona --rom roms/srallyc.zip --autostart

Headless check (no window, no audio device):

    build-srallyc/m2run build-srallyc/rom_cache/srallyc 3000 --inputs inputs.txt --wav out.wav

Status: boots, runs attract mode and races, music and effects play, and the
"SOUND BUFFER FULL" message no longer appears. Not tested: link play, the
native audio engine (it is Model 2 only), long-session stability, other
Model 2A games. Daytona was only smoke-tested (it boots and runs 600 frames).

## What was added or changed

### 1. Recompiling the Sega Rally program
* **Missing i960 instructions.** The recompiler had no native template for
  several floating-point and carry operations Sega Rally uses: `atanr`,
  `remr`, `sqrtr`, `cmprl`, `cpysre`, `cvtilr`, `scalerl`, the sin/cos/tan,
  log/exp families and their long forms, plus `addc`/`subc`. All were added
  to `tools/m2recomp/main.cpp` with the semantics of the reference core
  (`src/refcore/i960_ref.cpp`).
* **Program runs from RAM.** The game copies ROM `0x1000..` (0x60000 bytes)
  to RAM `0x5a0000` and executes there. `m2recomp` gained
  `--ram-overlay BASE:ROMOFF:SIZE` so code at the RAM address is compiled from
  the ROM bytes; `scripts/recompile.py` passes `5a0000:1000:60000` for
  `srallyc`, and `scripts/seed_scan.py` uses the same overlay.
* **Seeds.** `seeds/srallyc.txt` (about 750 entry points, generated by
  `scripts/seed_scan.py --append`, converged at ~65,000 reachable
  instructions in 44 chunks) and `seeds/srallyc_snd.txt` (sound 68000 jump-table
  targets).

### 2. TGP program
Sega Rally has no TGP ROM; the game uploads a 1665-word MB86233 program
from the main program ROM (offset 372372, CRC `0x072484B1`).
`src/runtime/rom_import.cpp` extracts it, and the build always uses the
generated TGP code. `src/runtime/tgp_stub.cpp` covers sets without one.

### 3. Model 2A sound board (68000 + SCSP)
Model 2 (Daytona) uses a 68000 + YM3438 + 2x MultiPCM. Model 2A uses a
68000 + Yamaha SCSP, with a different memory map (from MAME `model2.cpp`):

| Range | Contents |
|---|---|
| `0x000000-0x07ffff` | sound RAM (shared with the SCSP); first 16 ROM bytes copied here at reset |
| `0x100000-0x100fff` | SCSP registers |
| `0x600000-0x63ffff` | sound program ROM (reset PC `0x600100`) |
| `0x800000`, `0xa00000`, `0xe00000` | sample ROM and its two banks |

* `src/runtime/snd_cpu.{h,cpp}`: `Cpu68k` has an SCSP mode with this map.
* `tools/m2sndrecomp/main.cpp`: `--board scsp` maps the ROM at `0x600000`
  and seeds from the reset vector; `--seeds` takes extra entry points. The
  `4efa` jump tables at `0x600884`, `0x601666`, `0x6022c0`, `0x60279a` are
  seeded in `seeds/srallyc_snd.txt`.
* `src/runtime/scsp.{h,cpp}`: the SCSP, ported from MAME (see
  `THIRD_PARTY.md`): slots, envelope, LFO, pan, timers, interrupts, MIDI
  in/out FIFO, DMA and the effects DSP (`scspdsp`). Output is 44.1 kHz stereo.
  The DSP and DMA are ported but the game only barely exercises them, so
  they are the least tested parts.
* `src/runtime/sound_board.{h,cpp}`: `SoundBoard` selects SCSP mode when the
  sound program's reset PC is `0x6000xx`. Commands from the i960's UART go
  to the SCSP MIDI input; SCSP MIDI output goes back to the UART receive
  side. The 68000 clock is scaled for the 11.2896 MHz board.
* `src/app/main.cpp`: opens the audio device at 44.1 kHz for the SCSP board.
* `src/runtime/rom_import.cpp`: Sega Rally ROM set tables (`kSrallycb`).

### 4. Main-board fixes needed for sound commands
* **Hardware timers (`0x00f00000-0x00f0000f`).** They never counted. The game
  sends sound bytes from a timer 0 interrupt (reloaded to 50000 ticks, 2 ms),
  so the command queue filled and "SOUND BUFFER FULL" appeared. The timers now
  count at 25 MHz and raise request bit `2+n` on expiry, scheduled exactly
  through the lockstep callback queue. The lockstep count is instructions,
  so 25 MHz ticks are divided by `kCyclesPerInsn` (4; a 434k-cycle frame is
  about 110k instructions).
* **i8251 UART receive side** in `src/runtime/m2_board.cpp`: status lane
  and data lane so the game can read MIDI-out bytes from the sound board.

### 5. Tools
`tools/m2run` gained `M2_SND_INJECT=<hex>` (inject sound command bytes at
frame 60) and prints the MIDI-out byte count. `tools/m2import` knows the new
ROM set.

## Debugging aids left in
`SCSP_TRACE` (sound_board.cpp) and `UART_TRACE` (m2_board.cpp) print SCSP
register writes and UART traffic when set. They do nothing otherwise.

## Known gaps / next steps
* The SCSP is ported from MAME `master`, not a pinned commit; pin it.
* The timer divisor (4 cycles per instruction) is an estimate; exact timing
  would need a cycle-accurate count.
* No automated tests for the SCSP or the Model 2A path yet.
* Native audio (`--audio native`) is Model 2 only.
* Link play and force feedback were not tested with Sega Rally.
